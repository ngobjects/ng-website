glytta

A Java web framework in the spirit of WebObjects

Free and open source. Components pair an HTML template with a Java class, and glytta apps deploy alongside your existing WO apps.

Why glytta

Most web frameworks make you translate: state into URLs, clicks into routes, pages into JSON and back. In glytta you write the page, and the framework keeps track of the rest.

  • A click is a method call

    Bind a link to a Java method. glytta remembers the page it was on, so the method runs with all its state in place. No route, no form parsing, no IDs in hidden fields.

  • Templates are HTML

    Plus a few dynamic tags: <wo:str>, <wo:if>, <wo:repetition>. Bindings like $user.name resolve against your component's plain getters and fields.

  • Components all the way down

    A page is a component. So is a menu, a table or a form row. Each is a template and a class; they nest, and take bindings like HTML tags take attributes.

  • Update part of a page

    Wrap something in an update container and re-render only that, from the same component action. No front-end build.

  • Mistakes show up where they happen

    Misspell a key and the error renders in place, in the page, with a suggestion: "Did you mean 'title'?" Templates reload on every request.

  • Plain Java

    Java 25 and a standard Maven project. Apps deploy beside existing WebObjects apps, under wotaskd and JavaMonitor.

Status

glytta is under active development, and it's already running production sites. Interim releases (the 0.1.x series) are on Maven Central, and Java 25 or later is required.

We're in the "make the API nice" phase: the framework works, and what we learn from using it shapes how it ends up. So expect APIs to change between releases until 1.0, and these docs to grow. Ideas and feedback are very welcome.
